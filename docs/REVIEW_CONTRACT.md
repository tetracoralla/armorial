# Review contract

A current reviewer should re-run the source and runtime checks rather than accept this document as proof.

Product-specific adversarial sequences:

1. Search an exact English name, a Chinese title/tag, a multi-word query where one candidate covers more effective terms, and an English string that merely contains an icon name internally (for example `clockwise` / `lock`); verify relevant deterministic order, bounded results, and word/hyphen/camel boundaries without weakening controlled Chinese substring matching.
2. Resolve a tied Chinese intent without a semantic policy choice; verify no SVG is invented or arbitrarily selected.
3. Add a policy semantic selection; verify exact and ordinary English/Chinese phrasing resolve to it in one core/MCP call with the context style applied, while a multi-semantic intent does not get swallowed by the pin.
4. Render the same icon twice; verify byte-for-byte identical SVG even for icons that use internal ids.
5. Supply an SVG-breaking color, unknown policy field, duplicate normalized semantic key, unknown icon id, oversized query, and oversized batch; verify stable pre-render failures.
6. Render every IconPark metadata entry once; verify every entry maps to a renderer and generated output contains no script, event handler, external URL, or unbounded payload.
7. Execute the MCP server over stdio; verify five model-visible tools plus one `app`-only helper, run success, ambiguity, per-item batch failure, and visual-picker paths, and read the bounded MCP App HTML resource.
8. Launch the built CLI and MCP entry points through package-style symbolic links, including a path containing spaces; verify both processes actually start and the direct tools execute.
9. Run repeated hot semantic searches over the full pinned corpus and enforce the current runtime latency budget.
10. Launch the built local UI on loopback; search, select a non-default result, copy SVG, download, inspect drag transfer types, and verify Copy for Agent contains the canonical id and hash but no SVG.
11. In an Agent-hosted MCP App, verify grid selection sends nothing, Attach only updates context, Select & continue sends one user-role decision message, and a host rejection retains the selected icon plus Copy for Agent recovery.
12. At a narrow viewport, verify category navigation remains reachable, the grid and inspector remain usable, and the page has no horizontal overflow.
13. Pass a per-call `render` override through resolve, get, batch, and browse (core and MCP); verify it layers over the context policy, the result reports the final effective style, deterministic bytes stay deterministic, and stroke weights outside the IconPark integer `1–4` scale (including `0.5`, `2.5`, and `5`) fail before rendering. Verify policy version `1` fails with a migration message. Copy a v3 decision after picker adjustments and verify `get_icon` with the decision's `render` reproduces the exact `assetSha256`; verify Reset returns the policy-rendered asset.
14. Build and import `figma-plugin/manifest.json` in Figma Desktop. On a disposable acceptance page, verify click insertion creates a genuine Component master named `Icon/<slug>`, disabling the option creates a normal editable frame, and the inserted node is selected at the current viewport center.
15. In one Figma sequence, change theme, colors, size, stroke width, linecap, and linejoin; then enable outline and exercise preserve, flatten, and Boolean union. Independently reacquire the inserted nodes and verify current type, dimensions, hierarchy, naming, editable geometry, and absence of partial residual nodes after any failed operation.
16. Enter compact Drag mode and verify the plugin exposes usable canvas space; drag an icon onto the acceptance page and into a safe frame, then verify the final parent and relative placement. Attempt a drop over an instance or component set and verify Armorial falls back without mutating that target. Return to Settings, close and reopen the plugin, and verify both appearance and output settings are restored from Figma client storage.
17. Build the Pages artifact and verify its task-language HTML page, Markdown alternate, `llms.txt`, Sitemap, exact `source-commit.txt`, and deployed MIME types. Verify `/armorial/robots.txt` is absent rather than misrepresented as an origin-level crawler policy. Follow the published commit probe from a fresh checkout when judging the public distribution lane.
18. Render the 20 largest current IconPark responses as one batch and verify both the core result and complete MCP envelope remain inside their declared byte budgets. Keep direct CLI/library batch automation separate from model-mediated batch use.
19. Measure a fresh MCP process and its live `tools/list`: verify exact-id/name resolution can complete with zero alternatives before semantic-index construction, repeated identical searches reuse bounded ranking work, the complete catalog stays below 10 KiB, and model-visible batches reject more than 8 ids while the direct core retains its 20-id boundary.
20. In the built browser, repeatedly load the full 2,658-icon catalog. Verify rendered option/image/DOM counts remain viewport-bounded; measure append latency, tail behavior, heap, and depth trend under both ordinary and sustained loading; and verify `aria-posinset`/`aria-setsize` retain exact logical position while keyboard End reaches the last loaded item without leaving stale focus or selection. Without a current product SLO, report the measurements and any growth as a baseline rather than converting them into a mechanical performance PASS.
21. From a fresh installed Skill without MCP, first request several semantic icon ids without an artifact and verify the Agent uses one carrier-free `batch --resolve-intents --format json` process rather than a resolver subprocess per icon. The result must emit no SVG, preserve input order with explicit indexes, report a bounded intent/id mapping, and deduplicate shared ids in its summary. Then retrofit a multi-icon HTML artifact. Verify the Agent inventories every actual consumer, including text-glyph, breakpoint-only, close, disclosure, state, and empty-state icons, and uses one carrier-backed `batch --resolve-intents` process rather than a resolver subprocess per icon. On any compact ambiguity or miss, both routes must report all resolved mappings plus every unresolved intent and bounded candidates before publication rather than stopping at the first failure. The Agent may choose/refine only those unresolved entries; it must not individually re-resolve already reported mappings. Exactly one successful direct-CLI artifact batch either exclusively creates a deterministic same-origin `--output` sprite or creates a distinct, non-overwriting, marker-bounded HTML candidate with `--inline-from <source> --output <new-candidate>`. The source must remain byte-identical; same paths, hard-link aliases, and existing outputs must close without changes. Candidate JSON must include `sourceSha256`, `candidateSha256`, and `protectionLevel: non_overwriting_candidate`, without describing hashes as atomic commit credentials. A later consumer-patch retry must reuse unchanged generated output. Verify the Agent never prints or reads the generated geometry, no partial/duplicate or unused symbol is published, surrounding interaction/style bytes are preserved except for necessary icon references, conditional consumer rules such as first/last-child, responsive, state, and disabled exceptions retain the same inclusion set, favicons/logos/illustrations remain unchanged unless explicitly in scope, every `<use>` resolves, and a real browser reports non-zero rendered geometry. The browser verification should return compact counts and failing ids rather than a full page dump when no wider diagnosis is needed. Verify no text-glyph icon fallback appears, the Agent does not inspect or execute a source checkout, and it never defaults to an optimistic overwrite route.
22. On the managed CLI route, repeat resolve/get/batch with an explicit typed appearance override and verify the same effective style and asset hash as the core/MCP route. For a carrier-backed batch, verify `--format json` succeeds on the first call and still publishes only the sprite to the file/inline carrier; reject `--format text`, `--size` (which belongs to each consuming `<svg>`, not `<symbol>`), and invalid/fractional render flags before mutation.
23. In the human workbench, fail one debounced search after a successful paginated catalog. The failure may preserve already usable icons behind an error, but it must not expose a load-more action that can append the failed query or category to that older catalog. After the next successful search, pagination must resume from that successful basis only.
24. Under a restrictive caller umask, create a new SVG and verify its `0644` default is narrowed rather than broadened by the publication helper. Passing `--allow-optimistic-overwrite` for a nonexistent SVG must return stable `INVALID_INPUT` with no final output or temporary residue. Verify a pre-existing SVG output closes byte-identically by default. Then explicitly accept its optimistic replacement and reproduce the final check-to-rename window; every success must disclose `protectionLevel: optimistic_preflight_only` plus `concurrencyWarning`, retain the existing path and mode, and report a hash of the actual published bytes. Create one safe HTML candidate from a source with restrictive file permissions; it must inherit the source mode without changing the source. The explicit optimistic HTML route must also preserve the target mode. No route may silently broaden access or bypass path confinement.
25. For `--inline-from <source> --output <new-candidate>`, place body- and Armorial-marker-looking text inside script raw text and HTML comments, and exercise mixed-case/attributed, missing, self-closing, and repeated body start tags. Only one explicit, unambiguous HTML body node may be projected into a candidate; every rejected source and pre-existing output must remain byte-identical. Load one accepted candidate in a real browser and verify surrounding scripts still execute, the intended body remains selected, every `<use>` resolves, and rendered geometry is non-zero.
26. Put a complete marker pair in `<head>`, directly under `<html>`, and after the explicit body. Each source and packaged CLI route must return `INVALID_INPUT` with process exit 2, empty stdout, and byte-identical input rather than leaking an internal traversal failure. On source, Registry-installed, and immutable Plugin CLIs, start from exact 8 MiB caller-owned HTML and create first, retry, and changed distinct candidates with `--format json`; all three operations must succeed within the 8 MiB caller + 512 KiB managed block + four canonical framing-byte contract, while a no-marker caller input one byte over 8 MiB must fail without creating output. Then measure fresh 1, 4, 7.5, and 8 MiB valid candidate calls, assert the 5-second parser admission boundary, the current 6-second runtime boundary, and a conservative 256 MiB aggregate-RSS boundary formed by adding the parent and publisher process maxima; reject oversized tokens, nesting, node counts, and files before publication. Preserve original source bytes and every byte slice outside the inserted or replaced marker block in the candidate.
27. On source, built, Registry-installed, staged Plugin, and immutable Plugin routes, generate a safe HTML candidate while another editor performs both a same-size in-place source save and an editor-style replacement-inode save after Armorial reads it. The editor version must remain exact; Armorial must never change the source. Candidate output, when published, must remain bound to its reported `sourceSha256` and declare `protectionLevel: non_overwriting_candidate`. Race another creator for the candidate name and verify Armorial closes while preserving that creator's exact output and leaving no temporary residue. Separately reproduce both editor-save forms in the legacy `--inline-into --allow-optimistic-overwrite` final check-to-rename window. The route is permitted to overwrite there only because it is explicit opt-in; every success must disclose `protectionLevel: optimistic_preflight_only` plus the final-window `concurrencyWarning`, and current docs and Skill must forbid treating the preflight or hashes as an atomic compare-and-swap.
28. In the workbench, settle one query and select a result, then start a different query. While the replacement query is pending, after it fails, and after it returns no matches, Copy for Agent, Copy SVG, Download, standalone SVG drag, Attach, Select & continue, Figma insert, and Figma drag must not export or bind the old icon to the new intent. Disabled drag must expose no `image/svg+xml`, `text/plain`, or `DownloadURL` transfer data. After a successful replacement result, each selection-delivery or export action must use that settled query basis.
29. For safe HTML candidate creation, ordinary SVG output, and explicit optimistic HTML replacement, replace the already-admitted output parent with a symlink to a directory outside the task root immediately before publisher startup and immediately after the publisher has validated its cwd inode. Run both timings through source, built, Registry-installed, staged Plugin, and immutable Plugin CLIs. The pre-start swap must close before writing. The post-pin swap may publish only to the admitted directory inode; the replacement directory and any competing target must remain byte-identical. Every success hash must match the actual published bytes, source/candidate hard-link aliases and raced aliases must close, and controlled helper exit and partial-write failures must leave no final output. Under an ordinary writable parent those failures leave no temporary file. Separately revoke parent unlink permission only after full staging and require the surviving CLI to preserve the original cancellation/deadline cause while reporting bounded no-effect, cleanup-failure, and exact private-residue state. Keep all race/failure injection in test-only preloads: production source, built output, and immutable runtime bytes must not recognize a helper-import or injected-failure environment switch, and setting the retired test variable names must not alter a real publication.
30. Across source, built, Registry-installed, staged Plugin, and immutable Plugin CLIs, exercise SVG create/explicit replacement, HTML candidate creation, and legacy explicit replacement with 196-, 197-, and 255-byte destination basenames plus an exact 255-byte multibyte name. Each must use a destination-independent, short, exclusive temporary file inside the pinned parent and leave no residue. Exact 256-byte ASCII and multibyte basenames must return `INVALID_INPUT`, empty stdout, zero final output, and zero temporary residue. Inject an open failure before temporary creation and a partial-write failure followed by cleanup failure; cleanup must not run for the former or replace the causal error for the latter. Inject a temporary-handle close failure on all four publication routes before commit authorization: each must return its causal error with the final absent or byte-identically preserved and no residue. Separately fail removal of a create-mode private hard-link after publication and require a successful, hash/protection-truthful result carrying `cleanupWarning`; it must not report failure after commit. For the immutable package, distinguish Armorial first-party source/tests/hooks from dependency payload: report archive/unpacked bytes, entry counts, third-party declarations, non-declaration TypeScript, exact test-suite categories, package-runtime-protected paths, and intentionally retained runtime helpers. Derive protection from the current Host Node production conditions, exclude source/types/development-only branches, and verify all protected runtime targets and licenses remain rather than claiming unconditional zero source or tests.
31. Across source, built, Registry-installed, staged Plugin, and immutable Plugin CLIs, pause the pinned helper only after it has fully prepared and verified its private temporary file but before the CLI receives readiness. Kill only the CLI parent for SVG create, explicit SVG replacement, HTML candidate creation, and explicit optimistic HTML replacement. With an ordinary writable parent, the helper must observe IPC closure, publish no final output, preserve every competing target and source, remove its temporary file, and terminate without relying on the controller to kill its process tree. Repeat one route without killing the parent and withhold readiness through the five-second CLI deadline; it must close with no final output or residue. Revoke real destination-parent unlink permission after full staging and verify the deadline still reports its original cause plus structured `publication.effect: none`, failed cleanup, and a complete `0600` private residue; restore access and remove it only after assertions. Keep the later boundary honest: after the CLI validates readiness and sends the one-use commit token, force each carrier both to exit and to throw a structured helper error after publication but before its success summary. The CLI must return `PUBLICATION_OUTCOME_UNCERTAIN`, the actual final output must remain inspectable, and every current caller guide must require destination inspection before retry rather than claiming end-to-end cancellation atomicity. Also disclose that a truly abrupt create-only helper crash between hard-link publication and cleanup may leave its private sibling link.

## Boundary

These sequences are minimum coverage, not a completion certificate. Completing every item cannot by itself end a review: first reconstruct the current tool catalog, policy, picker, plugin, and release surfaces from source and a real run, keep at least one discovery route that is not copied from this list or the changed-file list, and report out-of-contract findings and untested compositions. A passing check run supports only its named observable; owner visual and task-fit acceptance remains separate.
